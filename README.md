# Юридичний AI-Агент: Трубопровід обробки документів

Цей проект являє собою повний цикл автоматизації обробки юридичних документів: від скрапінгу з офіційних сайтів до інтелектуальної сегментації статей за допомогою ШІ.

---

## 1. Скрапінг та збір документів (`scrape_of_courtsite_pdfs.py`)

Скрипт призначений для автоматичного моніторингу та завантаження аналітичних оглядів з сайту Верховного Суду України.

### **Функції та правила скрапінгу:**

- **Моніторинг**: Парсить сторінку [Аналізу ВСУ](https://supreme.court.gov.ua/supreme/pokazniki-diyalnosti/analiz/) на предмет нових PDF-посилань.
- **Уникнення дублікатів**: Перед завантаженням перевіряє файл у локальному реєстрі `agents/lists/list_of_pdfs.md`. Якщо файл уже є в списку, він ігнорується.
- **Нормалізація**: Очищає імена файлів від технічних префіксів та нормалізує їх для коректного збереження.
- **Завантаження**: Зберігає документи у MinIO у папку `pdfs/`.

### **Команди запуску скрапінгу:**

```bash
# Запуск у робочому режимі (завантаження та оновлення списку)
python3 agents/scrape_of_courtsite_pdfs.py

# Запуск у режимі тестування (без завантаження)
DRY_RUN=true python3 agents/scrape_of_courtsite_pdfs.py
```

## 2. Конвертація PDF у Markdown (`convert_pdfs_to_md.py`)

Цей модуль відповідає за перетворення бінарних PDF-файлів у текстовий формат Markdown, придатний для обробки штучним інтелектом.

### **Функції та правила конвертації:**

- **Розумна обробка**: Скрипт автоматично порівнює вміст папок `pdfs/` та `markdown/` у MinIO. Він конвертує лише ті файли, які ще не мають відповідної Markdown-копії.
- **Якісна конвертація**: Використовує бібліотеку `pymupdf4llm` для збереження структури тексту та таблиць.
- **Транслітерація**: Автоматично перетворює кириличні назви файлів у латиницю для стабільної роботи системних шляхів.
- **Структура збереження**: Результат зберігається за шляхом `markdown/{назва_документа}/{назва_документа}.md`.

### **Команди запуску конвертації:**

```bash
# Конвертувати всі нові PDF-файли
python3 agents/convert_pdfs_to_md.py

# Конвертувати конкретний файл за назвою (або частиною назви)
python3 agents/convert_pdfs_to_md.py Oglyad_ESPL_11_2024
```

## 3. Сегментація та структурування статей (`run_agent.py`)

Фінальний етап, на якому агент розбиває великі Markdown-файли на окремі юридичні позиції та перетворює їх на структурований JSON.

### **Функції та правила сегментації:**

- **Використання Skills**: Для максимально точної сегментації агент використовує файли-скіли з папки `agents/skills_for_markdownfiles/`. Вони містять точні маркери початку та кінця кожної справи.
- **AI-Аналіз**: Використовує модель `qwen2.5-coder:14b` (через Ollama) для виділення тези, номера справи, дати та категорії.
- **Збереження результату**: Структуровані дані завантажуються у MinIO у папку `structured/{slug}/`.

### **Команди запуску сегментації:**

```bash
# Запуск повної сегментації всіх нових документів
python3 run_agent.py

# Обробка конкретного документа
python3 run_agent.py Oglyad_ESPL_12_2024
```

### **Як користуватись "скілами":**

1. Створіть файл `.md` у `agents/skills_for_markdownfiles/`.
2. Вкажіть **Target File** (назву документа).
3. Опишіть сегменти:

   ```markdown
   ### [ID_Статті]
   - **Category**: Категорія
   - **Start**: Текст початку справи
   - **End**: Текст кінця справи (або початок наступної)
   ```

## 4. Ротація LLM-провайдерів (`llm_rotator.py`)

Для забезпечення безперебійної обробки великих обсягів документів та обходу лімітів (rate limits) хмарних API, у проекті реалізовано механізм автоматичної ротації провайдерів.

### **Як це працює:**

1. **Пріоритетність**: Агент намагається виконати запит через найшвидші хмарні провайдери у визначеному порядку:
   - **Groq** (llama-3.3-70b-versatile)
   - **SambaNova** (Meta-Llama-3.3-70B-Instruct)
   - **Cerebras** (llama-3.3-70b)
2. **Автоматичне перемикання**: Якщо один із провайдерів повертає помилку `429` (Rate Limit Exceeded) або технічну помилку, система миттєво перемикається на наступного у списку.
3. **Локальний Fallback**: Якщо всі хмарні сервіси недоступні або вичерпали ліміти, система перемикається на **локальний Ollama** (`qwen2.5-coder:14b`). Це гарантує, що процес обробки не зупиниться ні за яких обставин.

### **Переваги ротації:**

- **Стабільність**: Повна незалежність від стабільності окремих API або інтернет-з'єднання (завдяки Ollama).
- **Швидкість**: Максимальне використання безкоштовних/швидких лімітів декількох сервісів одночасно.
- **Економія**: Використання локальних ресурсів лише тоді, коли це необхідно.

## 5. Графічний інтерфейс користувача (`dashboard/`)

Для зручного моніторингу та керування юридичним агентом розроблено веб-інтерфейс на базі Streamlit.

### **Функції веб-інтерфейсу:**

- **📊 Метрики сховища**: Відображення загальної кількості PDF, структурованих документів та поточного розміру черги.
- **🤖 Моніторинг LLM-провайдерів**:
  - Візуалізація пріоритетів та черги ротації.
  - Можливість обрати пріоритетного (Preferred) провайдера з інтерфейсу.
  - Швидкий тест працездатності та швидкодії (latency) кожного API-провайдера.
- **🚀 Фоновий запуск конвеєра**:
  - Запуск обробки всієї черги або окремо обраного документа.
  - Відображення консольного логу виконання агента в реальному часі безпосередньо у веб-інтерфейсі.
  - Кнопка примусової зупинки фонового процесу.
- **📋 Провідник та редактор документів (Document Explorer)**:
  - Порівняльний перегляд оригінального тексту Markdown та структурованого JSON пліч-о-пліч.
  - **Інтерактивна форма редагування**: можливість коригувати розпізнану правову тезу, номер справи, дату, категорію та суд і миттєво зберігати виправлені дані локально та у сховищі MinIO.
  - Скачування фінальних JSON-файлів на комп'ютер.

### **Команда для запуску дашборду:**

Для запуску дашборду виконайте скрипт у корені проекту:

```bash
./run_dashboard.sh
```

Або запустіть Streamlit вручну:

```bash
python3 -m streamlit run dashboard/app.py
```

Адреса за замовчуванням: **<http://localhost:8501>** (або IP-адреса хоста у локальній мережі).

## ⚙️ Загальні вимоги для всього проекту

1. **Файл конфігурації**: Переконайтеся, що `.env.local` містить усі доступи до MinIO та API ключі провайдерів.
2. **Залежності**: Усі вимоги, включаючи хмарні клієнти та графічний інтерфейс, описані в `requirements.txt`. Встановіть їх командою:

   ```bash
   pip install -r requirements.txt
   ```

3. **Модель AI**: Для сегментації на етапі локального fallback переконайтеся, що Ollama запущений локально та модель завантажена:

   ```bash
   ollama pull qwen2.5-coder:14b
   ```
